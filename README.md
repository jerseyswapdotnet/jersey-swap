# SportsTranslate

Type any athlete, pick a sport, and get back the single best-matching equivalent athlete in
that sport — Lamine Yamal in the NBA comes back as Victor Wembanyama, Tiger Woods in the UFC,
whatever you want to know. Comes with a short, punchy explanation and side-by-side scores
(athleticism, dominance, fame, marketability, winning).

All athlete profiles and comparisons are generated by Claude, verified with live web search for
current team/position accuracy — there's no separate sports-stats API involved. A curated set of
well-known athletes across 8 sports (NFL, NBA, NHL, MLB, UFC, Soccer, Golf, Tennis) is
pre-generated via the seed script; anyone else is generated on the fly the first time someone
searches for them.

## Prerequisites

1. **Node.js 18+**
2. **An Anthropic API key** — create one at [console.anthropic.com](https://console.anthropic.com)
   (requires a billing method on file, even for light usage). Nothing in this app works
   without it, including the seed script.

## Setup

```bash
npm install
cp .env.example .env
# edit .env and set ANTHROPIC_API_KEY=sk-ant-...

npx prisma db push          # creates the local SQLite database
npm run seed                # pre-generates the curated athlete set (a few minutes, calls Claude)
npm run dev                 # starts the app at http://localhost:3000
```

## Adding more athletes to the curated set

Edit `src/data/seed-athletes.ts` — add a line like:

```ts
{ name: "New Athlete", sportKey: "nba" },
```

then re-run `npm run seed`. It's idempotent — already-seeded athletes are skipped, so you only
pay for (and wait on) the new ones.

## Refreshing a single athlete's data

If an athlete's team/accolades go stale (a trade, a new title), refresh just that one:

```bash
npx esbuild scripts/refresh-athlete.ts --bundle --platform=node --format=esm --packages=external --outfile=.refresh-bundle.mjs && node .refresh-bundle.mjs "Athlete Name" sportkey; rm -f .refresh-bundle.mjs
```

## How it works

- **Database**: SQLite via Prisma (`prisma/schema.prisma`). Three models: `Sport`, `Athlete`,
  `Comparison`. Comparisons are cached by `(inputAthleteId, targetSportId)` so the same lookup
  isn't regenerated.
- **AI generation**: `src/lib/generation.ts` has the functions that call Claude
  (`generateAthleteProfile`, `generateAthleteProfileAutoDetect`, `findEquivalentAndCompare`),
  used by both the seed script and the on-demand flow, so profiles stay consistent regardless of
  how they were created. Profile generation uses Claude's web search tool to verify current
  team/position rather than relying on training-data knowledge alone.
- **Search**: typing a name on the landing page hits `/api/athletes/search`, which queries the
  local database. If there's no match, a profile is generated on the fly, auto-detecting the
  sport if needed.
- **Translating**: `/translate/[athleteId]/[sportKey]` is a server-rendered page that fetches a
  cached comparison or generates a new one (matching + scoring + the matched athlete's profile)
  and stores it.

## Tech stack

Next.js (App Router) · TypeScript · Tailwind CSS · Prisma + SQLite · `@anthropic-ai/sdk` + Zod
for structured AI output.
